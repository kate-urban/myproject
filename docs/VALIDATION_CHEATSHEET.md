# Шпаргалка: сверка УП ↔ РПД ↔ ФОС

Краткая карта того, **откуда берутся данные**, **что с чем сравнивается** и **где править код**.

Страница UI: `http://localhost:8000/validation`  
Swagger API: `http://localhost:8000/docs`

---

## 1. Главная идея

**Учебный план (УП) — эталон.**  
РПД и ФОС должны совпадать с ним; ФОС дополнительно сверяется с РПД (если РПД загружена).

```
УП (plx/xlsx)  ──►  БД plan_disciplines
                           │
РПД (*.docx)   ──►  привязка по шифру ──► programs + rpd_extract_json
FOS (FOS_*.docx) ──►  привязка по шифру ──► programs + fos_extract_json
                           │
                           ▼
              validate_study_plan()      → R001–R030
              validate_study_plan_fos()  → F001–F014
                           │
                           ▼
                    отчёт JSON / HTML
```

---

## 2. Порядок работы на `/validation`

| Шаг | Действие | Результат |
|-----|----------|-----------|
| 1 | Импорт УП (`*.plx` или `*_plx.xlsx`) | Список дисциплин в БД |
| 2 | Загрузка РПД **с выбранным планом** | `linked: true`, шифр совпал с УП |
| 3 | Загрузка `FOS_...docx` **с тем же планом** | ФОС привязана к той же дисциплине |
| 4 | «Сверка РПД» | Отчёт R001–R030 по дисциплинам |
| 5 | «Сверка ФОС» | Отчёт F001–F014 |
| 6 | Скачать отчёт | JSON или HTML |

Если `linked: false` — сверка по этой дисциплине не пойдёт, пока шифр в файле не совпадёт со строкой УП.

## 3. Привязка документа к дисциплине

```
Имя файла + паспорт в Word
        │
        ▼
resolve_discipline_code()     ← app/utils/discipline_code.py
  B1_V_DV_01_01 → Б1.В.ДВ.01.01
        │
        ▼
Есть plan_disciplines.code = этот шифр в выбранном УП?
        │
   да ──┴── нет → discipline_not_in_plan
        │
        ▼
programs.document_id (РПД)  или  programs.fos_document_id (ФОС)
+ rpd_extract_json / fos_extract_json
```

| Файл | Роль |
|------|------|
| `app/services/rpd_linker.py` | Привязка, запись в `programs` |
| `app/api/endpoints.py` | `POST /upload/` + `study_plan_id` |
| `app/utils/link_messages.py` | Тексты ошибок привязки |

**РПД:** любой `*.docx` (не `FOS_*`).  
**ФОС:** имя начинается с `FOS_`.

## 4. Откуда берутся поля УП (эталон)

| Поле БД | Excel `*_plx.xlsx` | XML `*.plx` |
|---------|-------------------|-------------|
| `code` (шифр) | кол. **B** «Индекс» | `ДисциплинаКод` |
| `name` | кол. **C** | `Дисциплина` |
| `credits` (з.е.) | кол. **J** | `ТрудоемкостьКредитов` / `ЗЕТфакт` |
| `hours_total` | кол. **L** | `ЧасовПоПлану` |
| `hours_aud` | кол. **N** | агрегация `<ПланыНовыеЧасы>` |
| `hours_contact` | кол. **M** | то же |
| `hours_sr` | кол. **O** | то же |
| `hours_control` | часть разбивки часов | то же |
| компетенции | лист **Компетенции(2)** | `<ПланыКомпетенцииДисциплины>` |
| `department_code` | из плана | `КодКафедры` |
| направление / профиль | лист **Титул** | атрибут `Титул` у `<Планы>` |

**Файлы импорта:** `app/services/importers/plx_excel.py`, `plx_xml.py`, `study_plan_importer.py`

## 7. Формулы и «цифры» (РПД)

| Правило | Что сравнивается | Expected (УП) | Actual (РПД) |
|---------|------------------|---------------|--------------|
| **R005** | з.е. | `credits` | `credits` |
| **R020** | часы + СР | `hours_total`; `hours_sr` или `hours_sr + hours_control` | `hours_total`; `volume.sr` |
| **R022** | контакт | `hours_contact` или `hours_aud` | лек+практ из 1.3 или сумма тем |
| **R023** | СР | `hours_sr + hours_control` | `sr_table_total` или `volume.sr` |
| **R021** | минимум КР/КП | ≥40 ч (КП) / ≥30 ч (КР) | из таблицы 1.3 |

**Внутри одного РПД (без УП):**

| Правило | Формула |
|---------|---------|
| **R013** | `volume.sr` (1.3) = `sr_table_total` (3.5) |
| **R014** | контакт в 1.3 = `topics_contact_hours` (лек+практ+лаб из 3.1/3.2) |
| **R012** | нет одинаковых текстов ЗУV (warning, не ломает pass) |

**Вспомогательная формула в коде:**

```text
СР для сравнения с УП = hours_sr + hours_control   (функция _plan_sr_plus_control)
```

## 11. Статусы в отчёте

| Статус | Значение |
|--------|----------|
| **passed ✓** | правило выполнено |
| **failed ✗** | не совпало — смотрите `expected` и `actual` |
| **skipped** | нет данных или правило отключено |

**Дисциплина «прошла»:** все не-skipped правила с `severity: critical` = passed.

**Сводка по плану:**

| Поле | Значение |
|------|----------|
| `checked` | сколько дисциплин проверено |
| `passed` / `failed` | результат |
| `missing_rpd` | нет РПД |
| `missing_fos` | нет ФОС |
| `fos_only` | ФОС есть, РПД нет |

| Задача | Файл |
|--------|------|
| Импорт УП (Excel / XML) | `app/services/importers/plx_excel.py`, `plx_xml.py` |
| Шифр из имени файла | `app/utils/discipline_code.py` |
| Извлечение данных РПД | `app/services/rpd_extractor.py` |
| Извлечение данных ФОС | `app/services/fos_extractor.py` |
| Правила R001–R030 | `app/services/validation/rules.py` |
| Правила F001–F014 | `app/services/validation/fos_rules.py` |
| Запуск пакетной сверки | `engine.py`, `fos_engine.py` |
| Привязка DOCX к дисциплине | `app/services/rpd_linker.py` |
| API | `app/api/study_plans.py` |
| UI | `workspace.html`, `validation.html`, `index.html`, `static/js/` |
| Эталонные тесты | `docs/golden_pairs.yaml`, `tests/test_*` |

### Типичные правки

| Ситуация | Куда смотреть |
|----------|---------------|
| Неправильно считает часы | `rpd_extractor.py` (actual), `plx_*.py` (expected) |
| Слишком строгое сравнение названий | `_texts_match` в `rules.py`, `_discipline_names_match` в `fos_rules.py` |
| Новое правило R024 | функция + списки `RULES` и `DEFAULT_RULE_IDS` в `rules.py` |
| Порог F011 (50%) | `rule_f011`, строка `ratio >= 0.5` в `fos_rules.py` |
| Подписи директора / руководителя | `.env`: `EXPECTED_DIRECTOR`, `EXPECTED_DISCIPLINE_HEAD` |

### Добавить новое правило (шаблон)

1. Написать `def rule_r024(ctx) -> RuleResult:` в `rules.py`
2. Добавить `("R024", rule_r024)` в список `RULES`
3. Добавить `"R024"` в `DEFAULT_RULE_IDS`
4. Тест в `tests/test_*` или пара в `docs/golden_pairs.yaml`

| Правило | Разделы в UI | Суть |

## 17. Ограничения (не баг)

- R008/R009 — skip без переменных в `.env`
- R012, R029, R030 — warning (не блокируют «прошёл», но видны как замечания)
- Сверка **не пересобирает** Word — только отчёт
- Редактор `/` и сверка `/validation` — **разные** функции
- Старые загрузки без TZ-полей в JSON — нужна повторная загрузка или «↻ Из документа»

## 18. Шаблоны экспорта (папка `Layout/`)

| Файл | Имя в выпадающем списке |
|------|-------------------------|
| `Layout/Maket_RPd_FGOS_3.docx` | РПД FGOS 3 (макет) |
| `Layout/Maket_FOSd_FGOS_3.docx` | ФОС FGOS 3 (макет) |

При **старте сервера** макеты копируются в `templates/` и регистрируются в БД (`seed_layout_templates`).

### Экспорт на `/` (Document Processor)

1. «Открыть файл» → выбрать РПД `.docx`
2. «Загрузить» → разделы появятся слева
3. Редактировать нужные **разделы** в дереве слева (1.1, 1.2, 3.1 …)
4. При переключении раздела правки **запоминаются** автоматически
5. В «Шаблон:» выбрать **РПД FGOS 3 (макет)**
6. «Экспорт» → скачается DOCX (кнопка «Сохранить» не обязательна)

**Как подставляется текст:**

- если в шаблоне есть `{{Имя раздела}}` — замена по плейсхолдерам;
- иначе — **по заголовкам** (1.1., 1.2., 3.1. …): текст раздела вставляется под совпадающим заголовком макета.

Макеты СПбГЛТУ **без** `{{…}}` — работает второй режим (по заголовкам).

**Что попадает в файл:** текст разделов (1.1, 4.1 …). **Не попадает:** пустые таблицы паспорта и 1.3 в макете, шапка, подписи. Это **новый документ по бланку**, а не копия исходного Word.

После экспорта toast показывает «подставлено N из M разделов».

**Файлы:** `app/services/template_manager.py`, `app/services/export_by_headings.py`, `app/services/exporter.py`
