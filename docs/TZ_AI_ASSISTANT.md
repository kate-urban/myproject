# ИИ-помощник методиста

Краткое ТЗ на функцию «ИИ-помощник» в редакторе сверки (`/validation`).

## Цель

Помочь методисту **понять и исправить** ошибку сверки РПД/ФОС, не заменяя автоматические правила R/F.

## Пользовательский сценарий

1. Методист открывает дисциплину с ошибками → «Редактировать РПД».
2. Выбирает ошибку в списке или раздел с подсветкой.
3. В правой панели «ИИ-помощник» видит контекст (код правила, краткое описание).
4. Нажимает «Объяснить ошибку» или пишет свой вопрос.
5. Получает ответ: суть, где править, шаги.

## Ограничения

- Помощник **не меняет** документ и **не отменяет** правила сверки.
- Числа и коды берутся только из результата сверки и фрагмента раздела — LLM не должен «додумывать» эталон.
- Фраза «Не предусмотрены учебным планом» в тексте § 3.3 **не отменяет** проверки таблицы 1.3 (R022, R025 и др.) — это явно проговаривается в ответах.

## Контекст запроса

| Поле | Источник |
|------|----------|
| `rule_id`, expected/actual | `ValidationRuleOut` из сверки |
| `discipline_code` | строка УП |
| `section_title`, `section_snippet` | выбранный раздел + TinyMCE |
| Методичка | `docs/VALIDATION_CHEATSHEET.md` (фрагмент) |
| Справка по правилу | `app/services/validation/rule_guide.py` |

## API

```
POST /api/v1/assist/validation/
Authorization: Bearer … (если AUTH_ENABLED)
```

Тело: `ValidationAssistIn` → ответ `ValidationAssistOut` (`answer`, `source`: `local` | `llm`).

## Режимы работы

| Режим | Условие | Поведение |
|-------|---------|-----------|
| **local** | нет `AI_API_KEY` | Шаблонный ответ по rule_guide + expected/actual |
| **llm** | задан `AI_API_KEY` | OpenAI-compatible chat; при ошибке — fallback local |

Переменные окружения: см. `.env.example` (`AI_ASSISTANT_ENABLED`, `AI_API_KEY`, `AI_API_BASE`, `AI_MODEL`).

## UI

- Панель справа в модальном редакторе документа (`validation.html`).
- Бейдж: «справка» / «ИИ».
- Кнопка «🤖 Спросить помощника» в блоке подсказки по правилу.
- Быстрые промпты: объяснить / где править / шаги.

## Уровень 2: «Предложить исправление» (детерминированные правки)

| Правила | Область |
|---------|---------|
| R001–R005 | Паспорт, з.е. в табл. 1.3 |
| R020–R022, R025 | Часы в табл. 1.3 |

```
POST /api/v1/assist/suggest-fix/
```

UI: кнопка **«✎ Предложить исправление»** → diff → **«Применить и сверить»**.

## Уровень 3: «Правка (ИИ)» — LLM + diff + подтверждение

Для **любого** правила R/F (если настроен `AI_API_KEY`):

```
POST /api/v1/assist/suggest-fix-llm/
```

- LLM возвращает JSON: `explanation` + список `changes` (old/new подстроки из HTML).
- Сервер проверяет, что `old` есть в разделе; `apply_safe=true`, если `new` совпадает с эталоном сверки.
- UI: кнопка **«✨ Правка (ИИ)»** → модалка с diff и бейджем «ИИ» → **«Применить и сверить»**.

Файлы: `app/services/ai_fix.py`, `app/api/assist.py`, `static/js/validation_fix.js`.

Файлы уровня 2: `app/services/validation_fix.py`.
