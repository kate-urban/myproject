## 0. Назначение и границы

### 0.1. Цель системы

Автоматизация работы **двух методистов УМУ** по полному циклу учебно-методической документации:
   
1. Импорт учебных планов (УП) и программ (РПД, РПп, ФОС, ГИА).
2. Машинная сверка программ с УП и между собой.
3. Редактирование, переутверждение, экспорт Word/PDF.
4. Отчёты для планирования разработки и рейтинга авторов.
5. Архивирование (на позднем этапе).

### 0.2. Пользователи

| Роль | Количество | Права |
|------|------------|-------|
| Администратор (методист) | **ровно 2** | Полный доступ |
| Преподаватель | **0** | Роли нет |

- Самoregistration **запрещена** (`ALLOW_SELF_REGISTRATION=false`).
- Одновременное редактирование одной программы — **блокировка** с отображением «Занято [ФИО]».

### 0.3. Источник истины

| Данные | Источник истины | Примечание |
|--------|-----------------|------------|
| Часы, шифры, компетенции, кафедры | **Учебный план** (`.plx` / `*_plx.xlsx`) | Импорт в PostgreSQL |
| Тело программы (целевое состояние) | **PostgreSQL** (`program_*`) | Word/PDF — только export |
| Тело программы (текущее MVP) | `sections` (HTML) + `rpd_extract_json` | Миграция на `program_*` — этап P1–P2 |

### 0.4. Эталонные материалы

Все эталоны лежат в репозитории:

| Папка | Содержание |
|-------|------------|
| `samples/Информационные материалы/` | Макеты Word, Excel-отчёты, PDF переутверждения, «плохие» PDF |
| `samples/УЧЕБНЫЕ ПЛАНЫ/` | 301+ файлов `.plx` — источник УП |
| `docs/golden_pairs.yaml` | Эталонные пары УП ↔ РПД ↔ ФОС для тестов |

### 1.4. PDF — «плохие» документы (legacy / OCR)

| Файл | Страниц | Назначение |
|------|---------|------------|
| `B1_V_18_Smetnoe_delo_v_stroitelstve.pdf` | 42 | РПД дисциплины **Б1.В.18** «Сметное дело в строительстве» — legacy PDF |
| `FOS_B1_V_18_Smetnoe_delo_v_stroitelstve.pdf` | 20 | ФОС к той же дисциплине — legacy PDF |

**Характеристика «плохих» PDF:**

- Текстовый слой **есть**, но качество низкое: разрывные пробелы в словах (`Р А Б О Ч А Я`), нестабильная вёрстка таблиц.
- Парсер не должен полагаться только на `get_text()` — нужен fallback (OCR или ручной ввод паспорта).
- Пара **PDF ↔ DOCX** для той же дисциплины в папке **нет** — эталон «хорошего» варианта: загрузка `.docx` из других пар (`B1_O_13_...`).

**Требования к импорту PDF (модуль 2):**

1. Попытка извлечения текстового слоя (PyMuPDF).
2. Если паспорт (шифр, направление, з.е.) не распознан — **форма ручного ввода** + сохранение в `rpd_extract_json`.
3. Fallback OCR (`pytesseract` / `easyocr`) — этап P1; тесты на файлах из п. 1.4.
4. После импорта — редактирование в браузере и повторная сверка.

## 2. Архитектура

### 2.1. Стек

| Компонент | Технология |
|-----------|------------|
| Backend | Python 3.11+, FastAPI |
| БД | PostgreSQL |
| Парсинг Word | `python-docx` |
| Парсинг PDF | PyMuPDF; OCR — fallback |

## 3. Модули системы

### Модуль 1. Справочники

| Справочник | Требование | Эталон / API |
|------------|------------|--------------|
| ФГОС (УК, ОПК, индикаторы) | Редактирование только через справочник | `/api/v1/reference/fgos/` |

| МТО / аудитории | Список помещений | `/reference/mto/rooms/` (P2) |

### Модуль 2. Импорт и парсинг

| Формат | Требование | Статус |
|--------|------------|--------|
| УП `.plx` (UTF-16 XML) | Дисциплины, часы, з.е., компетенции, кафедра | ✅ |
| УП `*_plx.xlsx` | То же + формы обучения | ✅ |
| Word `.docx` / `.doc` | РПД, ФОС, РПп; привязка по шифру | ✅ |
| PDF (legacy) | См. п. 1.4 | ⚠️ текст без OCR |
| Пакетная загрузка папки | Автопривязка по имени файла | ✅ `/validation` |
| Нормализатор | ОПР-1→ОПР, мусор в 3.6 | ⚠️ только УП |

**Именование файлов:** `{Шифр}_{Тип}_..._k{NN}.docx`, префикс `FOS_` для ФОС.

### Модуль 6. Отчёты и экспорт

#### 6.1. Отчёт 7.1 — «Свод по УП»

**Эталон:** `2023_god_priema_SVOD_po_UP_FGOS3.xlsx`, лист `Лист1`.

**Колонки (строго в этом порядке):**

| № | Колонка | Источник |
|---|---------|----------|
| 1 | Учебный план | `study_plans.source_file` |
| 2 | Направление подготовки | `directions` + `profiles` |
| 3 | Код кафедры | `plan_disciplines.department_code` (из УП) |
| 4 | **Название кафедры** | `ref_departments` по коду |
| 5 | Шифр дисциплины | `plan_disciplines.code` |
| 6 | Наименование дисциплины | `plan_disciplines.name` |
| 7 | Объем дисциплины в з.е. | `plan_disciplines.credits` |
| 8 | **Автор** | Из **загруженной РПД**, поле паспорта **«ФИО автора РП и ФОС»** |

**Правило «Автор»:**

- Несколько ФИО — **каждое с новой строки** в одной ячейке Excel (как в эталоне: `Курова Н.В.\nКиносто М.С.\nСингуринди Э.Г.`).
- Если РПД не загружена — ячейка **пустая**.
- Формат ФИО: `Фамилия И.О.` (как в 7.2).

**API:** `GET /api/v1/reports/study-plans/{id}/plan-summary.xlsx`

**Приёмка AC-7.1:** побайтное совпадение структуры с эталоном; выборочная сверка 10 строк с ручным заполнением.

#### 6.2. Отчёт 7.2 — «Отчёт по разработке РПд»

**Эталон:** `Otchet_po_razrabotke_RPd_2025_1.xlsx`.

**Структура книги:**

| Лист | Содержание |
|------|------------|
| Справочник | Код кафедры → название |
| Преподаватели | Свод: ФИО, баллы, индикаторы, формулы |
| Сводная баллов | Итоги по авторам |
| Свод | Все дисциплины: шифр, УП, преподаватель, з.е., баллы |
| **Отдельный лист на каждого автора** | Детализация |

**Колонки детализации:**

- Дисциплина, Шифр, Учебный план, Преподаватель (многострочный)
- з.е., **Балл за 1 з.е.** (редактируемый, не только 20)
- Сумма баллов, Кол-во авторов, Баллов на автора
- **Кол-во баллов без повторов** (дубли в разных УП)

**Данные:** таблица `authors_load` + извлечение авторов из РПД.

**Приёмка AC-7.2:** ≥90% совпадение листов и формул с эталоном.
