# Целевая архитектура Syllabus (additive)

Документ описывает **целевую систему УМУ** и то, как она **наращивается поверх текущего MVP**, не ломая `/`, `/validation` и существующие API.

---

## Принцип: только дополнение

| Что | Статус |
|-----|--------|
| `/` — рабочее место (дерево УП, workspace) | **Основной UI** |
| `/editor` — редактор DOCX/PDF → HTML | **Legacy-редактор** |
| `/validation` — свerка УП ↔ РПД ↔ ФОС | **Сверка** |
| `POST /upload/`, импорт plx/xlsx, R001–R030, F001–F014 | **Сохраняется** |
| `/workspace` — новое рабочее место | **Добавлено** |
| `GET /api/v1/workspace/*` | **Добавлено** |
| Флаги в `.env` | **По умолчанию выкл.** — поведение как раньше |

---

## Точки входа

```
/                   ← рабочее место (workspace, дерево УП)
/editor             ← legacy-редактор TinyMCE
/validation         ← сверка УП ↔ РПД ↔ ФОС
```

---

## Флаги конфигурации (`app/config.py`)

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `AUTH_ENABLED` | `true` | Вход методистов; при `false` — один виртуальный admin без формы |
| `EDIT_LOCKS_ENABLED` | `false` | Блокировка `program` при редактировании; без флага — сохранение как раньше |
| `STRUCTURED_RPD_ENABLED` | `false` | Зарезервировано под таблицы РПД (этап 2) |
| `ADMIN1_USERNAME`, `ADMIN1_PASSWORD`, `ADMIN1_NAME` | — | Первый методист (при `AUTH_ENABLED=true`) |
| `ADMIN2_*` | — | Второй методист |
| `LOCK_TTL_SECONDS` | `900` | Время жизни блокировки без heartbeat |

Пример включения в `.env`:

```env
AUTH_ENABLED=true
EDIT_LOCKS_ENABLED=true
ADMIN1_USERNAME=ivanova
ADMIN1_NAME=Иванова
ADMIN1_PASSWORD=...
ADMIN2_USERNAME=petrova
ADMIN2_NAME=Петрова
ADMIN2_PASSWORD=...
```

## Этапы миграции

### Этап 0 — сейчас (реализовано)

- [x] Документ целевой архитектуры
- [x] `/workspace` + дерево `Год → Направление → Профиль → Дисциплины / Практики / ГИА`
- [x] Риббон: импорт УП, переход в legacy-редактор и сверку
- [x] Модели `admin_users`, `edit_locks`
- [x] API блокировок (не активен без флага)
- [x] Опциональная проверка блокировки в `PATCH /sections/{id}/` (только при `EDIT_LOCKS_ENABLED=true`)

### Этап 1 — авторизация и блокировки в UI

- [ ] Форма входа на `/workspace` при `AUTH_ENABLED=true` (каркас есть)
- [ ] Heartbeat блокировки из редактора (`/` передаёт `Authorization`)
- [ ] Отображение «Занято Ивановой» в `/validation` и legacy-редакторе
- [ ] Снятие блокировки при закрытии вкладки

**Не меняет:** формат данных, парсер, правила сверки.

### Этап 2 — структурированная БД РПД (параллельно HTML)

Новые таблицы **рядом** с `sections`, не вместо них на первом шаге:

```
rpd_passport          — паспорт (шифр, направление, профиль, год утверждения)
rpd_volume_rows       — таблица 1.3
rpd_topic_rows        — раздел 3.1
rpd_sr_rows           — раздел 3.5
rpd_competency_rows   — раздел 2
rpd_reapproval_rows   — сведения о переутверждении
fos_control_rows      — таблица контроля ФОС
```

Поток:

1. Загрузка DOCX → как сейчас → `sections` + `rpd_extract_json`
2. **Дополнительно:** миграция extract → нормализованные таблицы
3. Редактирование: сначала HTML (как сейчас), затем формы по таблицам за флагом `STRUCTURED_RPD_ENABLED`
4. Экспорт: из таблиц БД → шаблон Word (уже есть `Exporter`)

### Этап 3 — единый UI с вкладками разделов

- [ ] Встроить TinyMCE/формы в `/workspace` (вкладки вместо перехода на `/`)
- [ ] Риббон: Экспорт Word, Экспорт PDF с подписями
- [ ] Валидация и отчёты без перехода на `/validation`

Legacy-страницы остаются как «расширенный режим».

### Этап 4 — PDF, архив, отчёты 7.1

- [ ] `POST /export/pdf/` — генерация из БД + шаблон + подписи
- [ ] `archive_snapshots` — снимки утверждённых версий
- [ ] Импорт SVOD Excel (`2023_god_priema_SVOD_...`) — отдельный адаптер

## Роли и пользователи

**Цель:** только роль «Администратор», 2 человека, без преподавателей.

| Компонент | Файл |
|-----------|------|
| Модель | `app/models.py` → `AdminUser` |
| Сервис | `app/services/auth.py` |
| API | `POST /api/v1/workspace/login/` |

Преподаватели **не моделируются**. Расширение RBAC не планируется.

---

## Блокировки

**Цель:** Администратор 1 редактирует РПД → Администратор 2 видит «Занято …» и получает 409 при сохранении.

| Компонент | Файл |
|-----------|------|
| Модель | `EditLock` (`resource_type=program`, `resource_id=programs.id`) |
| API | `/api/v1/workspace/locks/` |
| Проверка сохранения | `app/api/endpoints.py` → `update_section` (если флаг включён) |

Старый редактор без заголовка `Authorization` при **выключенных** блокировках работает как раньше.

## Хранение данных

### Уже соответствует цели

- Учебные планы: `directions`, `profiles`, `study_plans`, `plan_disciplines` — **реляционно**
- Валидация: эталон УП в БД, extract JSON для сверки

### Промежуточно (MVP)

- РПД/ФОС: `documents` + `sections.content` (HTML из Word)
- `programs.rpd_extract_json` — для правил, не полная модель

### Цель

- Word/PDF **только на выходе** из `Exporter` + будущих таблиц этапа 2
- Word на **входе** остаётся как **канал миграции**, пока не заполнены таблицы

## Рекомендуемый порядок включения на проде

1. Развернуть с **выключенными** флагами → проверить `/`, `/validation`
2. Открыть `/workspace` → импорт, навигация, сводка
3. `AUTH_ENABLED=true` → настроить двух методистов
4. `EDIT_LOCKS_ENABLED=true` → обучить брать блокировку перед правкой
5. Этап 2+ по ROADMAP после согласования полей с УМУ
